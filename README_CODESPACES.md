# Запуск Payder в GitHub Codespaces

Эта конфигурация предназначена для временного тестирования полного приложения
(FastAPI + HTML/CSS/JavaScript + SQLite), а не для постоянного публичного хостинга.

## Как запустить

1. Загрузите содержимое этого проекта в свой GitHub-репозиторий.
2. Откройте репозиторий на GitHub и выберите **Code → Codespaces → Create codespace on main**.
3. Дождитесь окончания первичной настройки. Она установит зависимости и создаст локальный `.env`
   с уникальным `SECRET_KEY` и паролем администратора.
4. Откройте вкладку **Ports** в нижней панели VS Code. Должен появиться порт `8000` с названием Payder.
5. Нажмите на значок открытия браузера у порта `8000`. Если сайт нужен только вам, оставьте
   видимость `Private`. Если хотите дать ссылку тестировщикам, измените Visibility на `Public`.
6. Открывшаяся ссылка ведёт на Payder. Регистрация обычного пользователя доступна на сайте.

## Администрирование

Пароль администратора выводится один раз в терминал во время создания `.env`.
Сохраните его в менеджере паролей. Страница администрирования доступна по адресу `/admin`.

Если пароль потерян, остановите сервер, откройте `.env` в Codespaces и замените
`ADMIN_PASSWORD` на новый случайный пароль (не короче 12 символов), затем перезапустите сервер.

## Данные и перезапуски

- В тестовом режиме используется SQLite-файл `data/payder.db` внутри Codespace.
- Файл `.env` и каталог `data/` исключены из Git через `.gitignore`.
- Обычная остановка и повторный запуск того же Codespace сохраняют файлы рабочего пространства.
- Удаление Codespace может привести к потере его локальных данных. Перед удалением сделайте резервную копию БД.

## Важная безопасность

- Не вводите настоящие банковские реквизиты, пароли, PIN/CVV/CVC и коды подтверждения.
- Публичный порт означает, что сайт доступен всем, у кого есть ссылка; используйте только вымышленные тестовые данные.
- Не публикуйте `.env`, базу данных, резервные копии и секреты в GitHub.
- Codespaces может приостанавливать среду и не предназначен для постоянной работы публичного сервиса.
- Для реального запуска потребуются отдельный хостинг, резервное копирование, мониторинг и правовая проверка.
